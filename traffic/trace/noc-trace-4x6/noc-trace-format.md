# NoC trace：一颗 MPU 上一层 decode 的发包记录

## 内容与范围

这个目录记录一颗 MPU 的片上网络（NoC）在一层 decode 里的全部发包。执行安排（schedule）由分析模型给出，trace 从这份执行安排里导出。

四个窗口，各一个子目录：

| 子目录 | 每步处理的 token 数（S） | 层的种类 |
|---|---|---|
| `s1-layer-a` | 1 | a 型层 |
| `s1-layer-b` | 1 | b 型层 |
| `s4-layer-a` | 4 | a 型层 |
| `s4-layer-b` | 4 | b 型层 |

- **两种层**：a 型层比 b 型层多出 A07、A09、A10、A15 这几个算子的流量，其余算子两种层都有。
- **一个窗口 = 一层完整执行一次**：从层输入开始，经过注意力和 MoE，到层输出为止。
- **同一种层**：在一步里重复多次，每次的 NoC 流量相同。

范围：

- **网络**：4 行 × 6 列的 mesh，共 24 个 router。router 记作 `r<行>c<列>`，行 0–3，列 0–5。每个 router 挂一个 core。
- **路由**：维序路由。先沿行方向走到目标列，再沿列方向走到目标行。
- **记录的流量**：只有 router 之间链路上的流量。core 内部的数据搬运不经过 NoC，不在 trace 里。

## 次序和依赖

**`after`（依赖）**

- 含义：这条记录开始发送之前，必须已经送达的记录。
- 来源：执行安排里的数据依赖与同步关系，包括：
  - 接收方读取收到的数据；
  - 同一个 warp 内指令的先后；
  - barrier 的等待。
- 只列最近的一层：如果 A 已经在 B 的依赖链上，B 又在 C 的 `after` 里，C 的 `after` 就不再列 A。这一步是传递约简。

**`seq`（router 内的发送次序）**

- 同一个 router 上各条记录的发送先后，从 1 开始编号。

**`lclock`（逻辑时钟）**

- 计算方法：沿依赖链计数。`after` 为空的记录 `lclock` = 1，其余记录的 `lclock` = `after` 里最大的 `lclock` + 1。
- A 在 B 的依赖链上，就有 `lclock(A)` < `lclock(B)`；`lclock` 相同的两条记录之间没有依赖。

**用这份 trace 回放（例如驱动一个 NoC 模型）**

- 一条记录在它 `after` 里的记录全部送达之后，才可以发送。
- 如果还想保留这里每个 router 的发送次序，就让同一个 router 上 `role` = `send` 的记录按 `seq` 依次发出。

## 记录：一跳一条

一条记录 = 一个 router 把一份数据发往一个相邻 router。

各种消息拆成记录的方式：

- **单播（`unicast`）**：源 router 一条 `send`，沿路每个中间 router 各一条 `fwd`。
- **多播（`multicast`）**：一份数据沿一行或一列发出；也可以分两级，先沿一行（或一列）发出，再从途经的若干 router 沿列（或行）接着发出。
  - 源 router 一条 `send`，之后每一跳一条 `fwd`。
  - 途经的 router 如果是目的地之一，它的 core 收下一份，router 同时把数据继续往前传。
- **在网归约（`reduce`）**：一行或一列上的若干个 core 各有一份部分和（partial sum），在一个根 core 上求和。
  - 从离根最远的 router 开始，每个 router 把上游传来的部分和与本 core 的部分和相加，再发往下一个 router（`role` = `reduce`）。
  - 最后一跳（`role` = `reduce-root`）到达根 router。根 core 自己的部分和、以及根另一侧分支传来的和，在根 router 上加入，结果交给根 core。
  - 每一跳都是一条记录，`joins` 列出这一跳加进来的部分和来自哪些 core。
  - 途经的 router 上如果没有部分和加入，这一跳只把上游的和继续往前送，`joins` 为空。
- **全归约（`allreduce`）**：先做一次在网归约，再由根 router 把和沿原来的线路逐跳发回（`role` = `fwd`），线路上每个成员的 core 各收一份。

## 文件

每个窗口目录里有：

| 文件 | 内容 |
|---|---|
| `routers/r<行>c<列>.csv` | 这个 router 的全部发送记录，按 `seq` 排列，24 个文件 |
| `records.csv` | 全部记录，第一列是 router，按 `rec` 排列（即按 `lclock`，同一 `lclock` 内按 router 和 `seq`） |
| `messages.csv` | 一条消息（或一次集合通信）一行 |
| `links.csv` | 每条有向链路在这一层里承载的记录数与字节数 |
| `summary.json` | 按种类、阶段与算子的计数和字节数 |

记录编号 `rec`（`t` + 6 位数字）与消息编号 `msg`（`m` + 5 位数字）只在本窗口目录内有效。

## 列

`routers/*.csv` 与 `records.csv` 的列：

| 列 | 含义 |
|---|---|
| `router` | 发出这条记录的 router（只在 `records.csv` 里） |
| `seq` | 这条记录在本 router 上的发送次序 |
| `rec` | 记录编号 |
| `msg` | 所属消息的编号：一次多播的各跳、一次归约或全归约的各跳共用一个编号 |
| `kind` | 消息种类：`unicast`、`multicast`、`reduce`、`allreduce` |
| `role` | 这条记录在消息里的角色，见下表 |
| `src` | 消息的源。单播与多播：发送的 core 所在 router。归约与全归约：提供部分和的全部 core 所在 router |
| `dst` | 消息的全部目的地。单播：接收的 router。多播：每个收下一份的 router。归约：根 router。全归约：收到和的全部 router |
| `next` | 这一跳发往的相邻 router `r<行>c<列>` |
| `bytes` | 这一跳携带的字节数 |
| `joins` | 只用于 `reduce` 与 `allreduce` 的归约跳：这一跳加进来的部分和来自哪些 core，用分号分隔。`r<行>c<列>` 表示在本 router 加入；带 `@next` 表示在下一个 router 加入（最后一跳上根 core 自己的部分和）；`x<n>` 表示同一个 core 交了 n 份（这个 core 的部分和分在 n 个 subcore 上，各交一份）；空表示这一跳没有部分和加入 |
| `after` | 依赖：这条记录发送之前必须已送达的记录编号，用分号分隔 |
| `lclock` | 逻辑时钟 |
| `stage` | 所属阶段：`attention` 或 `moe` |
| `op` | 所属算子的编号，见文末的算子表 |

`role` 的取值：

| `role` | 含义 |
|---|---|
| `send` | 本 router 的 core 把一份新数据注入网络（单播与多播的源） |
| `fwd` | 转发从相邻 router 收到的数据（单播的中间跳、多播的后续跳、全归约的回程） |
| `reduce` | 在网归约的一跳：把上游的部分和与本 core 的部分和相加，发往下一个 router |
| `reduce-root` | 在网归约的最后一跳：和在下一个 router（根）上完成并交给根 core |

`messages.csv` 的列：`msg`、`kind`、`stage`、`op`、`src`、`dst` 的含义同上。其余几列：

- `bytes`：各跳携带的字节数。
- `records`：这条消息有几条记录。
- `routers`：经过的 router，按 `lclock` 先后排列。
- `lclock_first` / `lclock_last`：第一条和最后一条记录的逻辑时钟。

`links.csv` 的列：

- `link`：有向链路，`r<行>c<列>>r<行>c<列>`。
- `records`：这一层里走过这条链路的记录数。
- `bytes`：这些记录的字节数之和。

## 算子

算子按在层里首次出现的先后编号：注意力阶段是 A01–A21，MoE 阶段是 M01–M09。表里只写各算子的通信形态。

|---|---|---|
| `attention` | A01 | RMSNorm 的平方和：在第 0 列上在网归约到一个 core，再沿原线路发回 |
| `attention` | A02 | 层输入（bf16）从第 0 列沿行广播（只在 S = 1 的窗口里出现） |
| `attention` | A03 | 层输入（量化后）沿行广播 |
| `attention` | A04 | 投影：部分和在网归约，结果沿行、列分发 |
| `attention` | A05 | 归一化的平方和：汇总到一个 core，再广播 |
| `attention` | A06 | 投影输出发往汇总它的 core |
| `attention` | A07 | 投影：部分和在网归约，结果沿行、列分发（只在 a 型层） |
| `attention` | A08 | 投影：部分和在网归约，分片发往做注意力计算的 core |
| `attention` | A09 | 本步的一条记录发往保存它的 core（只在 a 型层） |
| `attention` | A10 | 权重沿列广播（只在 a 型层） |
| `attention` | A11 | 本步的一条记录发往保存它的 core |

| `attention` | A14 | 发往做注意力计算的 core（沿列、沿行） |

| `attention` | A16 | 各段注意力部分结果的合并：在网归约、汇总与广播 |
| `attention` | A17 | 注意力输出沿行分发 |
| `attention` | A18 | 投影结果汇总到各自的 core |
